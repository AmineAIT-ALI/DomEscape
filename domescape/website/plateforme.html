CONCEPTS CLÉS

Six idées qui définissent la plateforme.

Architecture événementielle

Chaque interaction commence par un événement physique. Les capteurs émettent, le moteur interprète, les actionneurs répondent.

Logique pilotée par la base

Scénarios, étapes, capteurs attendus et actions sont stockés dans MariaDB. Aucun changement de code pour créer un nouveau scénario.

Boucle de feedback physique

Les actions correctes déclenchent de vraies réactions physiques : messages LCD, prise connectée activée ou éteinte.

Supervision en temps réel

L'interface Game Master se synchronise automatiquement avec l'état de la session — progression, score, erreurs, télémétrie.

Séparation des responsabilités

EventManager, GameEngine et ActionManager sont des modules entièrement découplés, chacun avec une responsabilité unique.

Scénarios configurables

Chaque étape, déclencheur, action et séquence est configurable via la base de données. Un moteur, une infinité de scénarios.

INGÉNIERIE

Construit sur des principes solides.

Serveur sans état
PHP + MariaDB

PHP lit l'état depuis MariaDB à chaque requête. Aucune session en mémoire. Résistant aux pannes.

Middleware IoT
Domoticz + dzVents

Domoticz abstrait toute la complexité Z-Wave. dzVents relie la couche IoT à la couche applicative via webhooks.

Observabilité totale
100% tracé

Chaque événement, validation, action et transition est enregistré en base pour le debug et l'analyse.

Modèle plateforme
∞ Scénarios

Le jeu d'évasion est un scénario parmi d'autres. Le moteur exécute n'importe quelle narration pilotée par capteurs.
